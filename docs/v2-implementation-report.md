## Architecture and routes

Astro renders CMS pages on demand with the Cloudflare adapter. Sanity published reads use `useCdn: false` and the date in UTC; HTML and dynamic XML are `no-store`. A missing configuration or Sanity failure is an error, and an unknown content slug is a 404. This reduces freshness complexity but incurs an origin read and latency on each request. There is no shared cache or cache invalidation endpoint. Static fingerprinted assets remain cacheable.

Routes implemented: `/`, `/blog`, `/blog/[slug]`, `/blog/tags/[tag]`, `/portfolio`, `/portfolio/[slug]`, `/resume`, `/resume/view`, `/resume/download`, `/about`, `/contact`, `/api/contact`, `/feed.xml`, `/sitemap.xml`, `/robots.txt`, and the independent `/studio` shell and nested paths. Legacy blog, feed, contact, resume, icon and share-image redirects are handled in middleware. Portfolio fragment redirects run in the browser because fragments are not sent to the server. `/resume` remains the canonical experience address. Unknown routes and content return 404; validated PDF asset URLs redirect to Sanity, and a missing PDF returns to the CV.

The new presentation is an editorial redesign. Articles retain Portable Text prose, figures and captions, galleries, highlighted code, links, notes, callouts, embeds, revisions, related content, contents and RSS. The experience list is available without JavaScript; the optional Three.js timeline loads after activation and relates selectable nodes to CV entries. Project viewers load after activation and retain a poster. Theme choice is saved locally; the visualizations honor reduced motion and clean up their resources.

Intentional differences and limits: legacy OG paths redirect to a shared static card; current articles and projects use their Sanity covers for Open Graph when present. The Three.js experience and procedural rack have been redesigned rather than reproducing the old flight animation and exact model geometry. Model hotspot callouts and model-specific scale annotations are not yet reproduced. Contact's no-JavaScript alternative is the public LinkedIn profile because Turnstile itself requires JavaScript. Browser print styling exists, but matching the prior exact two-sheet layout has not been established. These are intentional differences from the prior design.

## Deployment prerequisites and remaining checks

Cloudflare needs the public Sanity identifiers and Studio build identifiers, exact Turnstile site key and hostname allowlist, a Turnstile secret, Resend API key, recipient and verified sender, and the configured `CONTACT_RATE_LIMIT` binding. Configure secrets without committing them or exposing them in logs. Preview and production hostname allowlists must be separate from localhost. Rate limiting is per location and eventually consistent, not a strict global sending budget. Sanity Studio requires CORS and authentication for each intended origin.

Before any later cutover, verify production data and every old URL; complete a real human Turnstile challenge and replay rejection, authenticated Studio editing, and PDF delivery. The user subsequently authorized a contact test; its live result belongs in the deployment status report. Review layout, print output and viewer behavior with actual content. Confirm headers, preview noindex, CPU/bundle limits and latency. Do not send real email or mutate CMS content from automated tests. Keep the Vercel deployment available for rollback. Restore the previous routing and webhook/cron to roll back.
