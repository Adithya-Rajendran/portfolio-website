## Architecture and routes

Astro renders CMS pages on demand with the Cloudflare adapter. Sanity published reads use `useCdn: false` and the date in UTC; HTML and dynamic XML are `no-store`. A missing configuration or Sanity failure is an error, and an unknown content slug is a 404. This reduces freshness complexity but incurs an origin read and latency on each request. There is no shared cache or cache invalidation endpoint. Static fingerprinted assets remain cacheable.

Routes implemented: `/`, `/blog`, `/blog/[slug]`, `/blog/tags/[tag]`, `/portfolio`, `/portfolio/[slug]`, `/resume`, `/resume/view`, `/resume/download`, `/about`, `/contact`, `/api/contact`, `/feed.xml`, `/sitemap.xml`, `/robots.txt`, and the independent `/studio` shell and nested paths. Legacy blog, feed, contact, resume, icon and share-image redirects are handled in middleware. Portfolio fragment redirects run in the browser because fragments are not sent to the server. `/resume` remains the canonical experience address. Unknown routes and content return 404; validated PDF asset URLs redirect to Sanity, and a missing PDF returns to the CV.

The new presentation combines an editorial portfolio with a procedural JavaScript robotics-and-space hero. Its rover and horizon are illustrative, not representations of the owner’s hardware. The generated raster concept is a planning reference only and is not served as the hero; see [artwork provenance](hero-artwork.md). Articles retain Portable Text prose, figures and captions, galleries, highlighted code, links, notes, callouts, embeds, revisions, related content, contents and RSS. The experience page pairs the real CMS work and education record with an automatically opening Three.js orbital view of Earth, Moon, Mars, Jupiter and Saturn. On mobile, the heading precedes the compact scene and the record follows it. These worlds are illustrative and independent of the factual CV entries below; a textured poster and the full CV remain available without JavaScript or on rendering failure. Controls support orbit, zoom, world selection, reset and pausing motion. See [the orbital design brief](v2-orbital-experience-design.md). Project viewers load after activation and retain a poster. Writing, project, About, Contact and error pages share the editorial visual language; contact result pages preserve the same presentation. Theme choice is saved locally; the visualizations honor reduced motion and clean up their resources.

Intentional differences and limits: legacy OG paths redirect to a shared static card; current articles and projects use their Sanity covers for Open Graph when present. The orbital experience and procedural rack have been redesigned rather than reproducing the old flight animation and exact model geometry. Model hotspot callouts and model-specific scale annotations are not yet reproduced. Contact's no-JavaScript alternative is the public LinkedIn profile because Turnstile itself requires JavaScript. Browser print styling exists, but matching the prior exact two-sheet layout has not been established. These are intentional differences from the prior design.

## Deployment prerequisites and remaining checks

Cloudflare needs the public Sanity identifiers and Studio build identifiers, exact Turnstile site key and hostname allowlist, a Turnstile secret, Resend API key, recipient and verified sender, and the configured `CONTACT_RATE_LIMIT` binding. Configure secrets without committing them or exposing them in logs. Preview and production hostname allowlists must be separate from localhost. Rate limiting is per location and eventually consistent, not a strict global sending budget. Sanity Studio requires CORS and authentication for each intended origin.

Before any later cutover, verify production data and every old URL; complete a real human Turnstile challenge and replay rejection, authenticated Studio editing, and PDF delivery. The user subsequently authorized a contact test; its live result belongs in the deployment status report. Review layout, print output and viewer behavior with actual content. Confirm headers, preview noindex, CPU/bundle limits and latency. Do not send real email or mutate CMS content from automated tests. Keep the Vercel deployment available for rollback. After production routing changes, disable the old Sanity webhook and Vercel publishing cron and monitor errors, contact delivery, 404s and content freshness. Restore the previous routing and webhook/cron to roll back.

The Cloudflare-injected analytics beacon is allowed by its specific script host; automatic beacon reporting uses the existing same-origin connection permission. This does not change analytics settings. A focused security-header check covers public and Studio responses.
